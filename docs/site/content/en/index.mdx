## Why use Prex?

Two Git worktrees can carry identical configuration. That includes the default port. If both apps ask the OS for port 3000, only one can listen there. You can assign a port manually, but the change also needs to reach browser URLs, API endpoints and any other tools that depend on the server.

Prex gives each launch its own port allocation and passes those ports to the existing dev command. A foreground run is handy when you want to see the output. A named background session is handy when you need to close the terminal and find the preview again later.

## Start a server

Install with npm if you already have Node.js 22 or newer. See [installation](/en/docs/installation/) for the native binary and update channels.

```sh
npm install -g @jkxrx/prex
prex run -- node -e 'require("node:http").createServer((_, res) => res.end("Hello from Prex")).listen(Number(process.env.PREX_PORT), "127.0.0.1")'
```

Open the printed URL in your browser. The inline Node command listens on the exact port from `PREX_PORT`. Press Ctrl+C to stop it. When integrating your real app, find the flag or variable it accepts and pass the assigned port there. For recipes, see [configuration](/en/docs/configuration/).

## Keep it running

Use the same launch in the background:

```sh
prex start --name hello -- node -e 'require("node:http").createServer((_, res) => res.end("Hello from Prex")).listen(Number(process.env.PREX_PORT), "127.0.0.1")'
prex list
prex status hello
prex stop hello
```

The first command waits for the port to open and prints a URL. The second shows sessions for the same user and state directory. The third gives details about this session, including its log. The last command asks the worker to shut it down.
