## From project to preview

In your project directory, put `prex run --` in front of your usual launch command. This example uses a Next.js dev server, which reads the assigned port from `PORT`.

<figure className="prex-flow">
  <figcaption>A launch in three steps</figcaption>
  <ol role="list">
    <li>Prex reserves a free port.</li>
    <li>Your dev server reads the port from <code>PORT</code>.</li>
    <li>You open the printed URL.</li>
  </ol>
</figure>

```sh
prex run -- npm run dev
```

Open the printed URL in your browser. If the CLI is missing, see [installation](/en/docs/installation/). Press Ctrl+C to stop it. When integrating your real app, find the flag or variable it accepts and pass the assigned port there. For recipes, see [configuration](/en/docs/configuration/).

## Keep it running

Run the command in a named session to keep it running independently of your terminal.

```sh
prex start --name web -- npm run dev
prex list
prex status web
prex stop web
```

The first command waits for the port to open and prints a URL. The second shows sessions for the same user and state directory. The third gives details about this session, including its log. The last command asks the worker to shut it down.

## Where to go next

If you already know which services you need, [configure their port roles](/en/docs/configuration/). If you want to understand when ports are reserved and released, read [the architecture guide](/en/docs/architecture/).
