# RFC 0001 — Previews Extended als npm-CLI

Status: Entwurf · 23. November 2026

**Vorschlag:** Previews Extended, kurz **Prex**, gesprochen „Prax“. Repository und ausführbarer Befehl heißen `prex`. Das npm-Paket soll `@jackatdjl/prex` heißen. Die Registry führte beim Abruf bereits Pakete namens [prex](https://registry.npmjs.org/prex) und [prax](https://registry.npmjs.org/prax). Für [@jackatdjl/prex](https://registry.npmjs.org/@jackatdjl%2fprex) lieferte sie HTTP 404. Die Rechte am Scope sind vor dem Release zu prüfen.

## Bedienung

Nach der Installation soll die Kurzform direkt vor einen vorhandenen Startbefehl passen.

```sh
npm install -g @jackatdjl/prex
prex bun run dev
prex composer dev
prex run -- bun run dev -- --turbo
prex run -- node "scripts/dev server.js" --label "feature A"
```

`prex run [Optionen] -- <Programm> [Argumente…]` ist die eindeutige Langform. Bei der Kurzform beginnt der Kindbefehl am ersten Programmnamen. Prex gibt dessen Argumente als Array weiter und startet im aktuellen Verzeichnis mit geerbter Umgebung und Standard-Ein-/Ausgabe. Shell-Pipelines und Umleitungen bleiben Sache der aufrufenden Shell oder des Kindbefehls. Eigene Unterbefehle und globale Optionen sind reserviert. Bei einer Namenskollision funktioniert die Langform. [Node.js child processes](https://nodejs.org/api/child_process.html)

Prex meldet vergebene Ports auf stderr. Ein vergebener Port ist eine Startinformation. Ob die Anwendung dort lauscht, hängt vom Integrationsvertrag in [RFC 0003](0003-integrationen.md) ab. Im Vordergrund bleiben Eingabe und Logs wie beim direkten Aufruf verfügbar. Prex übernimmt den Exitstatus des Kindes und räumt seine Vergabe bei regulärem Ende oder Abbruch auf. Signalweitergabe durch Paketmanager und deren Kindprozesse gehört in die Plattformtests.

## Stack und Auslieferung

TypeScript und Effect 4 auf Node.js ab Version 22. Der npm-Registry-Tag `latest` zeigte beim Abruf auf Effect 4.1.5. Effect übernimmt Konfigurationsvalidierung, typisierte Fehler und Ressourcen-Lebenszyklen. Node stellt TCP- und Prozess-Primitiven bereit. Eine kleine Argumentweiche hält das fremde Argument-Array unverändert und behandelt die wenigen eigenen Optionen. Die Effect-4-CLI-API ist als instabil dokumentiert und für diese Weiche optional. Das npm-Paket enthält gebautes JavaScript mit Node-Shebang und `bin`-Eintrag. Ein Projekt darf trotzdem Bun, PHP, Java oder andere Werkzeuge starten. [Effect-Registry](https://registry.npmjs.org/effect) · [Effect CLI](https://effect.website/docs/v4/api/effect/cli/Command) · [Node-Releaseübersicht](https://nodejs.org/en/about/previous-releases) · [npm bin](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/#bin)

Rust wäre attraktiv für ein eigenständiges Binary ohne Node. Für npm als primären Installationsweg würde ein nativer Build pro Zielplattform mit passender Paket- oder Installationslogik hinzukommen. Der Vorschlag priorisiert deshalb TypeScript. Für 0.1 sind Linux und macOS vorgesehen. Windows ist eine offene Plattformentscheidung, insbesondere wegen Kommando-Shims und Prozesssignalen.

## Abnahme und offene Entscheidungen

- Ein lokal gepacktes npm-Artefakt lässt sich in einem frischen Verzeichnis installieren und mit `prex --help` starten.
- Ein Kindprozess erhält Leerzeichen, leere Argumente und eigene Flags unverändert. Tests decken Startfehler, Exitstatus und interaktiven Abbruch ab.
- Zur Diskussion stehen der Paket-Scope und Windows zum ersten Release.
